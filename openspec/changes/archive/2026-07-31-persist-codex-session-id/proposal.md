## Why

Chorus currently shows its internal daemon session business key as the session ID, but a Codex daemon resumes with the thread ID generated by `codex exec --json`. Users therefore copy an ID from the UI that `codex exec resume` cannot use.

## What Changes

- Capture the real Codex thread ID already emitted by `thread.started`.
- Persist that backend-owned ID on the corresponding daemon session without changing the Chorus business key used for routing turns.
- Return the backend session ID through daemon-session read APIs.
- Keep the existing session ID copy control unchanged while making it copy the real backend session ID; hide the control when no usable backend ID is available.
- Leave pre-change sessions without a backend ID; no historical backfill is required.
- Verify the copied ID can resume the same Codex conversation with `codex exec resume <id>`.

## Capabilities

### New Capabilities

- `backend-session-resume-id`: Synchronize, persist, expose, and copy the backend-owned session identifier required to resume a daemon conversation.

### Modified Capabilities

None.

## Impact

The change affects the `DaemonSession` schema, daemon turn lifecycle reporting, the Codex spawner/waker contract, daemon-session API projections, the conversation transcript header, and their unit/integration tests. It adds no external dependency and preserves existing Chorus session routing semantics.
