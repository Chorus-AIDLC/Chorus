## Context
Workspace is Company. User currently requires oidcSub; OIDC/default-auth paths and the existing project access resolver must remain compatible. Human authorization currently retains broad business permission bits while project memberships constrain private resources. Workspace Admin is a new human management privilege, not an Agent role preset or project bypass.

## Data Contract
Add `Company.localAuthEnabled Boolean @default(false)`; new local bootstrap sets true with oidcEnabled=false. Legacy companies retain false regardless of oidcEnabled. Reject conversion between local and OIDC by generic company editing.
Add User fields: `authType String @default("oidc")`, `username String?`, `localEmail String?`, `passwordHash String?`, `status String @default("active")`, `workspaceAdmin Boolean @default(false)`, `sessionVersion Int @default(0)`, `deletedAt DateTime?`. Local records use authType="local", normalized username/localEmail, email for display, random `local_<uuid>` oidcSub sentinel, status invited/active/disabled/deleted. Unique indexes (companyUuid,username) and (companyUuid,localEmail) allow legacy nulls and duplicate SSO emails without rewriting IdP data. Local usernames MUST NOT contain @; this disambiguates username/email login. Deleted identities remain reserved for history, unless a later scoped design explicitly releases them.
Add `UserCredentialToken`: uuid, companyUuid, userUuid relation, tokenHash unique, purpose invite/reset, sessionVersion snapshot, expiresAt, usedAt nullable, createdAt. Store only SHA-256 hash of >=32 random-byte token; URLs use opaque raw token. Include company/user indexes and migration SQL. Regenerate client; do not apply to production or existing .pglite.

## Local Account Service (Task 1 owns)
`src/services/local-user.service.ts` owns DTOs, validation, persistence, invitation/reset, bootstrap and management authorization. Export normalized identifier/password helpers, public user projection, local-login credential verifier for Task 2 and user-account-state helper if helpful. Password hashing uses existing bcryptjs with an explicit work factor and UTF-8 byte validation (12+ characters; reject >72 bytes to avoid truncation); no native dependencies.
`src/types/local-user.ts` exports `LocalUserDto {uuid,companyUuid,username,email,name,workspaceAdmin,status,createdAt}` (no hashes/version/tokens), `CredentialLink {url,expiresAt,purpose}`, bootstrap and mutation input types. All successful REST responses use existing `{success:true,data:...}` envelope. UUIDs only. Empty/oversized input and invalid status/role types are rejected.
- `POST /api/admin/companies/local` (Superadmin only): `{name,initialAdmin:{username,email,name?}}` -> `{company:{uuid,name,localAuthEnabled:true,oidcEnabled:false},user:LocalUserDto,credentialLink:CredentialLink}`. Company + invited admin + hashed token created atomically.
- `GET /api/workspace/users` (active human local Workspace Admin only): paginated query `page,pageSize` -> existing paginated envelope, public DTO rows.
- `POST /api/workspace/users`: `{username,email,name?,workspaceAdmin?:boolean}` -> `{user,credentialLink}` for an invited local account.
- `PATCH /api/workspace/users/[uuid]`: `{name?,email?,username?,workspaceAdmin?,status?:"active"|"disabled"}` -> `{user}`. Active requires a previously established password; invited users activate only through acceptance. Duplicate normalized identities conflict. Reset privilege/state changes invalidate sessions. Editing an invited username/email invalidates old links and returns a replacement link when needed, or rejects the edit with an actionable request to resend; never silently retain wrong-recipient credentials.
- `DELETE /api/workspace/users/[uuid]` -> `{user}` with deleted tombstone, password cleared and tokens invalidated, history untouched.
- `POST /api/workspace/users/[uuid]/credentials`: `{purpose:"invite"|"reset"}` -> `{user,credentialLink}`. Invite only for invited users; reset only eligible nondeleted users. Reissue invalidates previous links. Reset may revoke established local sessions immediately; acceptance always revokes previous sessions and owned keys as appropriate, without permanently destroying owner API keys on a password-only reset unless explicitly documented.
- `POST /api/auth/local/accept`: `{token,password}` -> `{accepted:true}`; atomically validate purpose, expiry, user state and generation, consume token and establish hash. Invite activates; reset preserves current eligibility (cannot re-enable disabled/deleted users). No implicit login; UI returns to unified login. Generic invalid-link response, no user info by probing.
Links target `/login/local/accept?token=<opaque>` using configured trusted server origin (`APP_URL` if present; otherwise a documented localhost development default), never arbitrary client Host. Administrator UI provides copy/share link and expiry. This is the delivery contract: administrators explicitly send the link through their chosen trusted channel; no silently attempted email or required external SMTP setup. Only authenticated administrator issuance responses contain the raw link; never logs, activity bodies or reports. Credential page avoids leaking token via referrers.
Lifecycle operations run in transactions with a per-company row lock or equivalent serializable retry. Guard the last active admin (including concurrent disable/delete/demotion); first bootstrap invited admin is protected while no active admin exists. Re-read actor state/role and tenant inside transactions so stale cookies or racing role changes cannot authorize mutations. Audit actor/action/target without credentials.

## Authentication Integration (Task 2 owns)
Task 2 owns `src/lib/user-session.ts`, auth context projection, API key owner checks, identify route, auth types and local login route. Read Task 1 work report/types before implementing; agree helper exports through comments if necessary.
- `POST /api/auth/identify` accepts new `{identifier:string}` and legacy `{email:string}`. Local nondeleted matching usernames/email contribute `{kind:"local",company:{uuid,name}}`. Extend IdentifyResponse with single `{type:"local",company}`; combined paths use existing `{type:"multi_role",roles}` augmented local kind. Existing single/multiple OIDC variants remain exact; local-only multiples use multi_role. Continue Superadmin/default email detection and current SSO suffix/account matching. Do not return user IDs/emails/roles/status or public workspace directory. Duplicate candidates are stable/deduplicated.
- `POST /api/auth/local/login`: `{companyUuid,identifier,password}` -> `{user:{uuid,email,name,companyUuid,workspaceAdmin}}` and secure HttpOnly user_session cookie with normal bounded lifetime (existing 1h). Only explicitly local company and active local account with a valid hash may log in. Query identity+company, never global findFirst. Generic invalid credentials for unknown/disabled/invited/wrong workspace/password. Timing-safe bcrypt comparison, dummy hash where needed.
- Add bounded throttle for discovery and local login/accept using existing repository rate-limit utility if available, otherwise a small centralized helper with finite cleanup/capacity. Return actionable 429 without revealing identity; use trusted client address rules and identifier/company as supplemental key. Document memory fallback in multi-instance deployments.
- Local JWT includes `sessionVersion` and an explicit local auth marker. On every local session/Bearer resolution, reload tenant-bound user/company; compare state, auth type, version; use current DB admin flag, never trusting JWT privilege. Old local tokens without version fail closed; legacy OIDC/default sessions remain compatible and receive account-state checks without silently being elevated.
- All owned Agent API-key validation reloads owner by company+uuid. Missing, cross-company, disabled/deleted (including invited local owner) rejects authentication. Preserve existing owner project membership ceiling and no-owner Agent behavior. Existing human business permission bits remain available, so do NOT zero ordinary users' Agent permissions merely because workspaceAdmin=false. Agents never become human Workspace Admins. Central REST/MCP authentication must share enforcement.
- Prevent default fallback from bypassing managed local account state or granting workspaceAdmin; reject routing a legacy default identity into explicitly local tenants. OIDC sync does not overwrite/reactivate local identity records; local companies cannot become OIDC through arbitrary callback/config overrides.

## Risks and Decisions
Identifier enumeration is inherent in requested pre-auth candidate selection; expose only workspace name/UUID/auth path and throttle. Keep SSO issuer/client config disclosure exactly at current public OIDC contract. Cookie generations are revocation, not reusable JWT privilege. Avoid changing all existing OIDC user's email uniqueness. An invitation is issued, not silently emailed; authenticated admin can copy it reliably. Bootstrap transaction prevents orphan local workspace. Scoped company row locking avoids concurrent last-admin removal. No live deployment or data conversion in this run.
