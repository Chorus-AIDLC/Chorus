# 评论唤醒失败恢复与精确 turn 归属

## Why

评论 @Leo 的控制事件已经到达本机，但后续 HTTP 取数失败会留下未执行且无法自动恢复的工作。隔离复现还确认失败去重会阻止后续恢复；线上 turn 历史与普通唤醒的 FIFO 上报实现表明，新聊天能够启动 agent，却可能把执行状态记到旧评论 turn 上，不能只重试请求或修正 UI 标签。

## What Changes

- 将“处理中”与“已成功入队”的去重状态分离，失败释放占位；同时保留通知与定向 turn 双通路的单次入队保证。
- 保留精确的通知、turn、连接与会话对应关系，使恢复不依赖通知仍然未读，也不根据“唯一同类型通知”猜测执行上下文。
- 在 SSE 持续在线时对失败的读取与路由进行有界退避重试，保留恢复责任并定期协调；增加超时、连接代际和停止保护。
- 普通唤醒及合并批次按实际接收的 turn UUID 推进状态，不把新的聊天错误归到最早 pending turn。
- 补充故障注入、双通路并发、恢复、归属与关闭测试，以及脱敏的底层错误诊断。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cli-daemon`: 增加可靠接收去重、连接内恢复、精确身份及停止边界要求；保留现有 session 串行、定向路由和批次合并语义。
- `daemon-wake-coalescing`: 新协议以精确批次成员结算 turn，旧协议保留计数式 FIFO 兼容。

## Impact

- CLI：event-router、backfill、daemon/control wiring、waker、turn reporter 和 daemon REST client。
- 服务端：通知与 turn 的持久化关联、pending-turn DTO、精确普通 turn/批次 admission；新增可空兼容字段及迁移（具体字段见 design）。旧客户端仍可使用既有协议，新客户端通过能力标记启用新语义。
- 不增加运行时依赖，不改 UI 文案掩盖故障，不自动修复存量状态。
- 工作授权：先完成取证、修复代码与隔离验证。运行中 daemon 的更新、重启、旧消息重放及线上部署均不在本次执行授权内。

## Acceptance

在独立测试环境中，评论到达后两条取数路径首次失败、SSE 心跳正常、随后网络恢复时，无需人工聊天或重启即可准确入队一次；后到聊天与原评论保持各自 turn 身份。失败、权限拒绝、旧数据歧义和停止边界不得通过猜测或跨实例转发来“恢复”。
